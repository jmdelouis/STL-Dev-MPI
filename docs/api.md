# API Reference

STL-Dev-MPI is a Cargo workspace of five crates. The complete API documentation is generated by
rustdoc:

```bash
cargo doc --no-deps --workspace --open          # or docs/build.sh: the site with the rustdoc under rust/
```

On the built site it is under <a href="rust/stl_core/index.html"><code>rust/</code></a>.

## Crates

| Crate | Role | Depends on |
|---|---|---|
| `stl-core` | HEALPix geometry, wavelet convolution and its adjoint on partial grids, decimation and pieces, the per-block forward and reverse sweeps (`LocalEngine`), coefficient plans, L-BFGS, the planar engine. Pure Rust, no MPI, `f64` | `cdshealpix`, `rustfft` |
| `stl-mpi` | decomposition into NESTED ranges, halo exchange and ghost accumulation, the distributed objective (`Objective`, `Ensemble`), npy / FITS I/O, the threads and MPI backends of `Comm` | `stl-core`, `rsmpi` (feature `mpi`) |
| `stl-gpu` | the sweeps on a CUDA device per rank (`GpuEngine`), device geometry (DIA or bound stencils), the objective's extra terms and harmonic transforms on the device, the planar engine on the device | `stl-core`, `cudarc` (driver and NVRTC loaded at run time) |
| `stl-cli` | the command-line tools and their objectives (ensemble, kappa, kurtosis, level power, marginal, Minkowski terms; `stl-ensemble`; planar) | the three above |
| `stl-bridge` | C ABI over the engines and L-BFGS for Python (`ctypes`): P. Campeti's driver, and the differentiable full-sky, masked, patch and spectrum engines of `stl_port.native` | `stl-core`, `stl-gpu` |

## Main types and functions

**Geometry and statistics** (`stl_core`)

| Item | What it is |
|---|---|
| `local::LocalGeometry` | the geometry of one nside, kernel and `L`, built per block on the fly (`new(nside, kernel_size, L, Gauge::Cosmo, block_pixels)`) |
| `engine::EngineConfig` | `J`, the level of every scale (`j_to_dg`), the S3/S4 definitions |
| `plan::build_plan`, `plan::Coefficient`, `plan::Family` | the ordered list of coefficients and their native levels |
| `engine::LocalEngine` | forward and reverse sweeps over the blocks of one partition: statistics, their spatial variances, map cotangents |
| `engine::Evaluator` | the trait shared by the CPU engine and `stl_gpu::GpuEvaluator` |
| `conv::convolution_forward` / `convolution_adjoint`, `local::modulus_vjp` | the elementary VJPs |
| `healpix::*` | `nest2xyf`, `ring2nest`, pixel centres, ring bilinear interpolation (port of the HEALPix C++ library) |
| `lbfgs::minimize`, `LbfgsOptions` | L-BFGS with strong Wolfe line search, transcribed from `torch.optim.LBFGS` |
| `precond` | per-scale preconditioners of L-BFGS (Haar bands) |
| `planar` | the 2D engine (periodic tiles, STL-Dev's `STL_2D_Kernel_Torch`) |

**Distribution** (`stl_mpi`)

| Item | What it is |
|---|---|
| `Comm` | the communicator trait (rank, size, sums, gathers, point to point); `threads::run_ranks` and `mpi_comm::MpiComm` implement it |
| `Decomposition`, `build_partition` | NESTED ranges per rank, held cells per level |
| `HaloExchange` | halo distribution and additive ghost reduction |
| `synthesis::Objective` | distributed loss and gradient for one target (`statistics`, `evaluate`), with the CPU or a GPU evaluator |
| `synthesis::Ensemble`, `run_lbfgs_with` | ensembles of members, L-BFGS over the distributed map |
| `io::read_map`, `read_map_range`, `write_npy`, `write_healpix_fits` | maps, read and written by owned slices |

**GPU** (`stl_gpu`)

| Item | What it is |
|---|---|
| `Gpu` | one device: context, stream, NVRTC-compiled kernels |
| `GpuEngine`, `GpuOptions`, `GpuEvaluator` | the device engine of a rank and its options (`FieldStore`, `GeometryCache`, `ConvForm`) |
| `terms` | ensemble, level power, marginal, kappa and kurtosis terms on the device |
| `GpuSht`, `harmonic` | spherical harmonic transforms for the C_ℓ, PDF and Minkowski terms of `stl-ensemble` |
| `planar` | `GpuPlanar`, `GpuPlanarTerms` |

## Using the library

The tools are thin layers over these types. `stl_cli::statistics_of_maps` (behind `stl-stats`)
is the shortest complete example; in outline:

```rust
use stl_core::{engine::EngineConfig, local::LocalGeometry, plan::{build_plan, Family}, stencil::Gauge};
use stl_mpi::synthesis::Objective;

// inside stl_mpi::threads::run_ranks(n, |comm| { ... }) or with an MpiComm
let geo = LocalGeometry::new(nside, 5, 4, Gauge::Cosmo, 16384);         // kernel 5, L = 4
let cfg = EngineConfig::new(j, false);                                    // J scales, standard S3/S4
let plan = build_plan(j, 4, &cfg.j_to_dg, 1, None, &Family::ALL);         // one channel, every family
let probe = Objective::new(&geo, &cfg, &plan, &target_stats, 1, 1, comm);
let (start, end) = probe.owned();                                         // this rank's NESTED range
let stats = probe.statistics(&x_owned);                                    // Vec<Complex64>, len(plan)
```

The synthesis driver is `stl_cli::run` (behind `stl-synth`); the ensemble method is
`stl_cli::ensemble`.

## Python

`stl-bridge` exposes the engines through a C ABI used by P. Campeti's Python package
(`python/stl_ensemble`); see [the merge report](campeti_merge.md), section 2. The module
`stl_port.native` wraps it with three differentiable engines (forward and exact VJP, CPU or GPU),
introduced in the user guide's page [Differentiable statistics in Python](user-guide/differentiable.md):

| Python class | C ABI | What it computes | Reference |
|---|---|---|---|
| `NativeEngine` | `stlp_new`, `stlp_forward`, `stlp_vjp`, `stlp_set_masks`, `stlp_native_pixels` | full-sky statistics of `B` maps, auto or cross (`cross=True`), averaged over the whole sky or over `K` masks | [Masked statistics](masked_statistics.md), [cross statistics](disc_cross_statistics.md) (section 1.2) |
| `PatchEngine` | `stlp_patch_new`, `stlp_patch_select`, `stlp_patch_forward`, `stlp_patch_vjp`, `stlp_patch_forward_device`, `stlp_patch_vjp_device` | statistics of disc patches (support radius `R`, averaging core `r`), auto or cross | [Disc patches](disc_cross_statistics.md) |
| `SpectrumEngine` | `stlp_spec_new`, `stlp_spec_set_masks`, `stlp_spec_forward`, `stlp_spec_vjp` | pseudo-`C_ℓ` (anafast, `iter=0`), spin 0 or spin `s` (`EE`, `BB`, `EB`), auto or cross, `K` masks | [Differentiable pseudo-spectra](spectrum.md) |

Also in `stl_port.native`: `delouis_transform` and `delouis_transform_vjp` (the
`sign · sqrt|·|` post-transform of Delouis et al. 2022), and `native_lbfgs` (the Rust L-BFGS
driven by a Python callback).
